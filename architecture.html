Architecture · ai-testing-academy

AI Testing Academy — how the whole thing is put together

A single-page React site that teaches QA automation and runs three AI-backed tools (resume review, mock interview, question-bank enrichment) entirely from the browser. There is no backend of its own: the user brings an API key, or an optional shared proxy in the monorepo answers for them. This page walks the runtime shape, the provider abstraction, the content model, and where to extend each one.

1 · What it is

One page, six sections, stacked in reading order. Three are static teaching content; three call a language model. Everything below exists to serve that split.

static ⚙️ Connection Setup Pick a provider and model, paste a key or lean on the server default, and test the round trip before anything else runs.
AI · JSON 📄 Resume & CV Agent Parses an uploaded PDF/DOCX in-browser, scores it as structured JSON, rewrites it, and exports the result back to PDF.
static 🎓 Lecture Series Course tracks and lecture links. Content lives in the component itself, not the locale files.
AI · chat 🎙️ Mock Interview A five-stage interviewer driven by one long system prompt, ending in a scored verdict on a sentinel token.
AI · grounded ❓ Interview Questions A curated bank, plus a “enrich with fresh questions” action that runs a web-grounded Gemini call.
static 🐍 Coding Challenges 40 Python problems across three levels — each a prompt, then a hint, then a solution with complexity.

2 · Runtime shape

The build output is static files. At runtime the browser is the whole application: it holds the key, it formats the request, it talks to the model vendor directly. The optional /api hop exists only so first-time visitors get a working demo without owning a key.

The two transports

default path Bring your own key The key stays in localStorage and is attached to a fetch() made from the page itself. Anthropic requires anthropic-dangerous-direct-browser-access for this to be allowed at all — that header is what makes browser-origin calls legal, and it is set deliberately.
fallback path Shared server proxy On mount the app probes GET /api/ai/config. If it reports Gemini as available and the user has not opted into their own key, calls route through POST /api/ai/generate instead, and no key ever reaches the client. A failed or missing probe simply returns {} — the site then insists on a user key rather than breaking.
Why the dev proxy exists. Vite's SPA fallback answers /api/* with index.html at HTTP 200, so res.ok passes and res.json() chokes on HTML — the site would silently conclude no server key exists and grey out the panel. vite.config.ts therefore proxies /api to the sibling api-server package (API_PORT, default 8787) in development. In production one origin serves both, so the relative path just works.

3 · Composition

App.tsx is a provider stack and nothing else. Each layer is there for a reason, and the order matters in exactly one place: ProviderContextProvider reads translated error strings, so it has to sit inside LocaleProvider.

QueryClientProvider — TanStack Query client; present for future server state, not yet on the hot path.
TooltipProvider — Radix tooltip root for the shadcn/ui primitives.
LocaleProvider — Resolves the language once, exposes locale / S, stamps lang and dir on <html>.
ProviderContextProvider — Owns provider/model/key state and the callClaude / callGrounded functions every AI feature uses.
WouterRouter — Base path taken from import.meta.env.BASE_URL, so the app works under a sub-path deploy.
Switch → HomePage | NotFound — One real route. The router is here for the sub-path handling and the 404, not for navigation.

Below the router

HomePage owns two pieces of page-level chrome — the theme and the nav drawer — and then renders the six sections in order. Everything else a section needs, it pulls from context itself. That is the reason the page component stays under 100 lines while the sections it renders are hundreds.

The shape to notice. No component imports a vendor SDK, a URL, or a key. They import useProviderContext() and call a function. Swapping a vendor, adding a proxy, or changing a header touches lib/providers.ts alone.

4 · The AI layer

lib/providers.ts is the only file that knows any vendor exists. PROVIDERS is a registry of strategy objects — one per vendor — behind a uniform interface, so the call site never branches on which one is selected. 

interface ProviderDef {
  label:        (S) => string;           // translated field label
  placeholder:  string;                   // key format hint, e.g. 'sk-ant-...'
  models:       string[];                 // first entry is the default
  validateKey?: (key, S) => void;         // fail fast on an obviously wrong key
  build:        (key, model, system, messages, maxTokens)
                  => { url, headers, body };   // vendor request shape
  parse:        (d) => string;            // vendor response → plain text
  keyHint?:     (key, status, S) => string;    // extra help on a 4xx
}

Three exported entry points

callAI()
The general path. Chooses proxy vs direct, validates the key, builds, sends, and parses — returning a plain string.
callGeminiGrounded()
Adds the google_search tool so answers cite live sources. Used only by the question-bank enrichment.
extractJSON()
Pulls a JSON object out of a model reply — strips a ```json fence if present, then takes the outermost braces. This is what makes “return only JSON” prompts survive a chatty model.

Failure handling is part of the contract

  • A thrown fetch (CORS, offline, blocked host) is translated into an explanatory message naming the host that was refused — not a bare TypeError.
  • A non-2xx response carries the status plus the first 300 characters of the body, so the user sees the vendor's own complaint.
  • A wrong-shaped key is rejected before any request is made, via validateKey — pasting an sk-ant- key into the OpenAI slot fails locally.
  • Every error string comes from the active locale, so the failure path is translated as carefully as the happy path.

5 · Content & i18n

en.ts is the source of truth for structure; he.ts is declared as const he: Locale where Locale = typeof en. That single annotation means the compiler rejects a Hebrew file that drops a key, misspells one, or falls behind a new section. Translation drift is a build error, not a runtime blank.

resolution order Which language wins ?lang= query param → localStorage.ata_lang → navigator.language starting with he → en. The result is written back to storage, so a link with ?lang=he is sticky.
direction RTL is data, not a branch Each locale carries its own dir. applyHtmlAttrs() stamps lang and dir onto <html> and CSS logical properties do the rest — no component checks the language.
switching Full reload, on purpose switchLang() writes the choice and reloads with the new query param. A reload guarantees direction, fonts and third-party widgets all re-lay out cleanly, which a re-render does not.
prompts Prompts live in the locale The resume, rewrite and interview system prompts sit under locale.prompts, so tuning model behaviour is a content edit — and each language can steer the model in its own words.

The challenge content model

lib/challenges.ts declares types only — no data. The UI depends on the shape, and the shape is currently satisfied by the locale files; an API or CMS could satisfy it later without touching a component.

6 · Feature modules

📄 Resume Agent — the heavyweight

At ~540 lines it is the largest component, because it is really a small document pipeline: read a file, extract text, score it, rewrite it, export it. All of it client-side.

extract

pdf.js or mammoth turns an uploaded PDF/DOCX into plain text in the browser.

→
score

callClaude() with the resume prompt, then extractJSON() into scores, strengths, gaps.

→
rewrite

A second call with the improve prompt returns ATS-friendly prose, not JSON.

→
export

jsPDF + html2canvas render the result back out as a downloadable PDF.

Those four libraries are not bundled. They are injected at runtime by loadFirst(), which walks cdnjs → jsDelivr → unpkg and stops at the first host that actually defines the expected global. The two parsers are also warmed on first interaction, so the upload does not stall on a cold CDN. It keeps the main bundle small, at the cost of a hard dependency on public CDN reachability.

🎙️ Interview Agent

A rolling Message[] is kept in a ref and resent whole on every turn — the model holds the conversation, the client holds no session. The five-stage structure lives entirely in locale.prompts.interview. Ending the interview sends the sentinel ___VERDICT___, which the prompt binds to “stop and produce a scored verdict”.

❓ Question Bank

Static stages render immediately. The enrich action feeds the user's role and a fixed keyword seed into callGrounded(), then extractJSON() lifts a questions array out of the reply. Grounding is why this one path is Gemini-only.

🐍 Coding Challenges

The section maps levels to ChallengeCards and knows nothing else. Each card owns its own useDisclosure(3) — prompt → hint → solution → collapsed — so the list never tracks a stage per index and adding challenges cannot regress the reveal logic.

7 · State & persistence

There is no store. State is React state in two contexts plus local component state, and the only thing that survives a reload is what is deliberately written to localStorage under the ata_ prefix.

KeyWritten byHolds

ata_langi18nResolved language, re-written on every resolve so it stays sticky.
ata_providerProviderContextSelected vendor; defaults to gemini.
ata_key_<provider>ProviderContextThe user's own API key, one slot per vendor, saved only while “use my key” is on.

resetSettings() clears every ata_ key and reloads — that prefix is the reason it can be a one-line sweep rather than a maintained list.

The key-mode decision

One subtlety worth naming: ownKeyTouched. Until the user explicitly toggles the switch, the app re-derives the mode whenever the provider changes or the server config arrives — a stored key or the absence of a server default turns own-key mode on. Once the user touches it, their choice is respected and never recomputed.

8 · UI mechanics

hooks/useDisclosure Stepped reveal A modulo counter over N stages. It knows nothing about hints or solutions, which is why the same hook drives any progressive-reveal card.
hooks/useReveal Scroll-in animation One IntersectionObserver per section adds .in and then unobserves, so each element animates exactly once and the observer disconnects on unmount.
Nav Scroll-spy A second observer with a -25% / -65% root margin highlights whichever section is in the reading band, not merely on screen.
HomePage Drawer without a flash The nav-ready class lands after a double requestAnimationFrame, so CSS transitions are only enabled after the first paint and the drawer cannot animate on load.
lib/domUtils Safe rendering of model text esc(), linkifyHtml() and findLinks() escape first and only then insert <strong>/<a> — markdown from a model is rendered without handing it an HTML injection.
lib/domUtils Mixed-direction output isRtlText() detects Hebrew per block, so a model reply can be aligned correctly even when it does not match the page language.

Accessibility affordances already in place

  • A skip link to #main-content, translated like everything else.
  • aria-expanded on every disclosure button, and aria-label on the icon-only nav and language toggles.
  • Theme is an attribute on <html> (data-theme), so CSS — not JS — resolves colour, and the first paint is already correct.
  • Both lang and dir are set on the document element, which is what screen readers and the bidi algorithm actually read.

9 · Trust boundaries

Be explicit about the key. In own-key mode the API key lives in localStorage and is sent from the page to the vendor. That is the accepted trade for a backend-free teaching site — any script running on this origin could read it, and the key is exposed to the browser's network log. The proxy path exists precisely so a casual visitor never has to make that trade.
  • Untrusted input is model output. Everything a model returns is escaped before it reaches the DOM; the markdown renderer builds its tags from parsed groups, never by interpolating raw text.
  • No secret is bundled. Server-side keys stay in api-server; the client only ever learns the boolean available and a default model name.
  • Error bodies are truncated to 300 characters before display, which keeps a verbose upstream error from dumping a wall of text into the UI.
  • Third-party script injection is real surface. The resume tools are pulled from public CDNs at runtime; a compromised CDN would execute on this origin. Pinned versions and a fixed host list limit, but do not remove, that exposure.

10 · Build & deploy

The package is one workspace inside a pnpm monorepo (artifacts/ai-testing-academy), alongside api-server, portfolio and the lecture sites. Shared dependency versions come from the workspace catalog, which is why so many entries read catalog:.

pnpm dev
Vite dev server, host 0.0.0.0, with /api proxied to the local API server.
pnpm build
Emits to dist/public with emptyOutDir.
pnpm serve
Previews the built output on the same port contract.
pnpm typecheck
tsc --noEmit — the gate that keeps he.ts aligned with en.ts.
Config fails loudly. vite.config.ts throws if PORT or BASE_PATH is missing or malformed, rather than defaulting. Under a sub-path deploy a silently wrong base produces a blank page with 404s on every asset — a startup error is far cheaper to diagnose.

BASE_PATH flows all the way through: Vite uses it for asset URLs, and App.tsx feeds import.meta.env.BASE_URL to the router so client-side routing agrees with the host. Deploy path is configured once, in one variable.

11 · Extension points

To add…TouchAnd nothing else, because…
A coding challenge or a whole level lib/locales/en.ts + he.ts CodingChallenges maps over whatever the locale provides; it never counts levels or items.
A model vendor lib/providers.ts — one ProviderDef The picker renders Object.keys(PROVIDERS) and callAI only ever calls build/parse.
A model to an existing vendor That vendor's models array The dropdown is generated from it; the first entry is the default.
A language A new locale file + the CATALOG map Typing it as Locale makes the compiler enumerate everything still missing.
A page section A component + one line in HomePage + a nav.links entry Scroll-spy and reveal both derive from the DOM and the nav list, so neither needs editing.
A progressive-reveal UI elsewhere useDisclosure(n) It is stage arithmetic only — it has no opinion about what a stage contains.

Where the edges are

  • Lecture content is hardcoded inside LectureSeries.tsx as EN/HE objects rather than living in the locale files — the one section that breaks the content/UI split.
  • Grounded search is Gemini-only, so the enrich action degrades if the user is on Anthropic or OpenAI without a Gemini key.
  • The proxy path covers Gemini only. The other two vendors are own-key or nothing.
  • Resume tooling needs the public internet beyond the model call; behind a strict CSP or an offline network, extraction and PDF export are the first things to fail.
